# AvaxCats Mint — lesson 1: plain HTML (anvil local → Fuji testnet)

NFT mint demo for the **Team Avalanche — Team1 VN** 🇻🇳 academy class.
Everything is minimal: 1 ERC-721 contract, 1 static web page, no backend,
no build tool, no IPFS (metadata + image embedded directly in the tokenURI
as a data URI).

```
mint-site/
├── index.html     # mint page (ethers.js v6 via CDN) — do NOT edit
├── config.js      # ← lesson 1's "env": paste the contract address here
├── cats.js        # 48 pre-embedded cats (generated by build_mint_site.py)
└── README.md      # this file
```

> **Where is the contract?** There is only ONE file for both lessons:
> [`../mint-dapp/contracts/AvaxCats.sol`](../mint-dapp/contracts/AvaxCats.sol).
> Previously each folder kept its own copy, and the two really did drift apart —
> the copy here still had the old `mint(uri)` while lesson 2 had moved to
> `mint(catId, uri)`. Deploying the old copy by mistake breaks lesson 2 completely.
> So the copy is gone for good: deploy 1 contract, both pages use it.

The page runs on **2 networks**, switched by exactly 1 line at the top of `index.html`:

```js
const NETWORK = "anvil";   // "anvil" = local on your machine | "fuji" = real testnet
```

## Option 1 — Run locally with anvil (no wallet, no faucet needed)

Needs **Foundry** (`anvil --version`); if you don't have it:
`curl -L https://foundry.paradigm.xyz | bash && foundryup`

**Tab 1 — start the local blockchain:**

```bash
anvil
```

**Tab 2 — deploy the contract.** Easiest is to borrow lesson 2's script:

```bash
cd ../mint-dapp && npm install && npm run deploy:anvil
```

It prints the contract address (and writes it to `mint-dapp/.env.local`).
Or deploy with foundry if you prefer (you must point it at OpenZeppelin —
it lives in lesson 2's `node_modules`, so you still need `npm install` over there):

```bash
forge create ../mint-dapp/contracts/AvaxCats.sol:AvaxCats \
  --remappings @openzeppelin/=../mint-dapp/node_modules/@openzeppelin/ \
  --lib-paths ../mint-dapp/node_modules \
  --rpc-url http://127.0.0.1:8545 \
  --private-key 0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80 \
  --broadcast
```

(The private key above is anvil's default account #0 — a public foundry
constant that only works on the local chain. This command also creates
`out/` + `cache/` folders, which can be deleted.)

**Tab 3 — paste the address into `index.html` and open the page:**

```js
const NETWORK = "anvil";
const CONTRACT_ADDRESS = "0x5fbdb2315678afecb367f032d93f642f64180aa3";
```

```bash
python3 -m http.server 8000
```

Open <http://localhost:8000> → click **Dev wallet (anvil)** → pick a cat →
**Mint NFT**. Done — no wallet popup, no fees.

> **Why no wallet?** Anvil exposes 10 accounts and auto-signs transactions
> sent to it — the page just calls `provider.getSigner(0)`. A real network
> never signs on anyone's behalf; that is precisely the wallet's job.

Check the result from the command line:

```bash
cast call <CONTRACT> "totalMinted()(uint256)"        --rpc-url http://127.0.0.1:8545
cast call <CONTRACT> "ownerOf(uint256)(address)" 1   --rpc-url http://127.0.0.1:8545
cast call <CONTRACT> "tokenURI(uint256)(string)" 1   --rpc-url http://127.0.0.1:8545
```

⚠️ Stopping anvil wipes all state — restart it and you must redeploy the contract.

## Option 2 — Deploy to Fuji testnet with Remix

### Step 1 — Prepare a wallet

1. Install **Core Wallet** (<https://core.app>) or **MetaMask** and create a new wallet.
   ⚠️ A learning wallet — never keep real funds in it.
2. Get test AVAX from the faucet: <https://build.avax.network/console/primary-network/faucet>
   (select the **Fuji C-Chain** network). If the faucet asks for a coupon, the instructor
   will hand out coupons or send test AVAX directly to the whole class.

### Step 2 — Deploy the contract with Remix

1. Open <https://remix.ethereum.org>, create a new file `AvaxCats.sol`, and copy the contents of
   [`../mint-dapp/contracts/AvaxCats.sol`](../mint-dapp/contracts/AvaxCats.sol)
   into it. ⚠️ It must be exactly this file — any version without `mint(catId, uri)` and
   `mintedBitmap()` is wrong.
2. **Solidity Compiler** tab → pick compiler `0.8.20` or newer → **Compile**
   (Remix downloads OpenZeppelin itself; wait a few seconds).
3. **Deploy & Run Transactions** tab:
   - Environment: **Injected Provider** (the wallet will pop up — make sure it is on
     **Avalanche Fuji**, chainId 43113)
   - Contract: `AvaxCats` → click **Deploy** → confirm in the wallet.
4. Copy the **contract address** you just deployed (under *Deployed Contracts*).

> Each student can deploy their own contract, or the whole class can share
> 1 contract deployed by the instructor — either works.

### Step 3 — Configure and run the mint page

1. Open **`config.js`** (not `index.html`) and paste the address you copied:
   ```js
   window.AVAXCATS_CONFIG = {
     NETWORK: "fuji",
     CONTRACT_ADDRESS: "0x...",   // the address Remix returned
   };
   ```
   Or let the machine fill it in — this command validates the address and writes it for **both lessons**:
   ```bash
   cd ../mint-dapp && npm run set-contract 0x...
   ```
2. Run a static web server right inside the `mint-site/` folder:
   ```bash
   python3 -m http.server 8000
   ```
3. Open <http://localhost:8000> → **Connect wallet** (the page switches to / adds the
   Fuji network automatically) → pick a cat → **Mint NFT** → confirm the transaction in the wallet.
4. After minting, the page shows a **Snowtrace** link to view the transaction + NFT:
   <https://testnet.snowtrace.io>. The NFT also appears in the Collectibles tab
   of Core Wallet.

## How does the page work? (reading the `index.html` code)

- **Config** — `NETWORKS` declares both networks' parameters in exactly the format
  wallets expect for `wallet_addEthereumChain`; `NET` is the selected network. Nowhere
  in the page is Fuji hardcoded anymore.
- **B1** — draws the grid of 48 cats from `cats.js` (32×32 images as data URIs).
- **B2a** — real wallet: `eth_requestAccounts` requests permission,
  `wallet_switchEthereumChain` switches network (falls back to `wallet_addEthereumChain`
  if the wallet doesn't have that network yet).
- **B2b** — dev wallet (anvil only): `new ethers.JsonRpcProvider(...)` +
  `getSigner(0)` — talks straight to the node, which signs on your behalf.
- **B3** — builds the tokenURI: standard ERC-721 JSON metadata (name, description,
  image, attributes) → base64 → `data:application/json;base64,...`
- **B4** — calls `contract.mint(uri)` via ethers.js, waits for the receipt, reads
  `tokenId` from the `Minted` event.

## Discussion questions for the class

- Why does this demo embed the image in the tokenURI instead of using IPFS?
  Pros/cons? (hint: gas cost of ~1KB storage vs. decentralisation)
- Anvil's "dev wallet" can sign for you; a real wallet makes you click confirm.
  What does that difference protect you from?
- How does `_safeMint` differ from `_mint`?
- What happens if 2 students mint the same cat?
  (hint: different tokenIds — an NFT is a token, not a picture)
- How would you limit each wallet to 1 mint? Try modifying the contract!
